# V2V 차량 협력 주행 임베디드 시스템 설계

## 1. 프로젝트 목표

- 여러 대의 차량 보드가 서로의 상태를 공유하며, 특정 이벤트 발생 시 급정지 / 감속 / 차선 변경 같은 동작을 협력적으로 수행하는 것을 목표로 한다.
- 개별 차량은 YOLO 모델을 사용하여 영상 기반으로 전방 상황을 인지한다. 추가로 날씨 및 도로 혼잡도 정보에 따라서도 차량 동작을 제어한다.

## 2. 프로젝트 인원 및 기여 내용

- 인원 : 총 4명
- 기여 내용
  - YOLOv8 모델 기반 영상 분석, 앞 차량과의 거리 및 급정지 유무 판단
  - V2V 통신으로 받은 다른 차량의 상태 정보를 바탕으로 동작을 제어 / 판단하는 로직 설계

1. 개별 차량은 영상 정보를 기반으로 앞 차량과의 거리, 급정지 유무를 판단한다.

3. 차량들은 다른 차량의 위치, 속도, 급정지 유무, 수동 입력 등을 바탕으로 현재 내 차량의 동작을 제어한다.
4. 국토교통부 역할을 하는 SoM 보드는 개별 차량에게 일방적으로 날씨와 혼잡도 정보를 전송한다. 개별 차량은 해당 정보를 바탕으로 동작을 추가로 제어한다.

## 5. 설계 - 코드별 기능 요약

### 개별 차량 보드

| 파일 | 기능 |
|---|---|
| Qt | 가상머신(VM)에서 사용자 수동 입력 버튼 GUI 생성 코드 |
| `v2v_comm.c/.h` | TCP P2P 연결, 송수신 |
| `v2v_topology.c/.h` | IP 판단 |
| `serial_gui.c/.h` | Qt 시리얼 수신 → event_type 변환 |
| `v4l2_interface.c` | 카메라 V4L2 제어, 영상 정보 읽기 |
| `wayland_npu_app.c` | **핵심 application** — 주행 영상 읽기, YOLOv8 모델로 객체 판단, 앞 차량과의 거리 및 급정지 유무 판단, 영상 기반 자차 상태를 다른 차량에 전달, V2V 기반 차량 제어 |

### 국토교통부 보드

| 파일 | 기능 |
|---|---|
| `v2v_comm.c/.h` | TCP 통신 (차량 보드와 공용) |
| `v2v_topology.c/.h` | IP → vehicle_id (차량 보드와 공용) |
| `v2v_molit_payload.c/.h` | 기상 / 혼잡도 → brake / lane 재해석 broadcast |

## 6. 핵심 코드 내용

### 1) V2V 통신

- 개별 차량 보드는 서버와 클라이언트 역할을 동시에 수행한다. TCP 연결을 통해 다른 차량들과 P2P 방식으로 데이터를 주고받는다.
- 차량끼리 주고받는 데이터는 아래와 같은 48byte 구조체(`V2VEventMsg`)이며 다음 정보를 담는다.

```c
V2VEventMsg (48 byte)
magic          : 수신 데이터가 유효한 V2V 메시지인지 검증하는 고정값
vehicle_id     : 송신 차량 번호
event_type     : 자차 수동 제어용 Qt 버튼 신호
timestamp      : 송신 시각
brake          : 개별 차량의 영상 기반 급정지 위험 (0/1)
front_distance : 영상 기반 추정 앞차와의 거리 (m)
position       : 직선 도로에서의 차량 위치
lane           : 차선 번호 (1~3)
speed          : 현재 속도
```

### 2) Qt 수동 입력 GUI

- Qt 수동 입력은 차량 운전자의 수동 제어를 표현한다.
- Qt에서 버튼을 누르면 `serial_gui.c`가 시리얼로 1글자(L, l, R, r, E, e)를 받아 event_type으로 변환해 전역 변수에 저장한다. 보드는 이 값을 자기 판단에 사용함과 동시에 다른 차량으로 보내는 `V2VEventMsg`의 `event_type`에 실어 보낸다.

### 3) Topology 처리

- 보드마다 자기 IP를 읽어 매핑표에서 vehicle_id(1, 2, 3, 국토교통부 100)와 연결할 상대 목록을 결정한다. 실행 인자나 하드코딩 없이 차량 보드 3대가 같은 코드로 동작한다.
- 연결은 vehicle_id가 작은 쪽에서 큰 쪽으로만 시작한다. 두 보드가 동시에 서로 연결을 시도해서 생기는 경합을 구조적으로 막고, 상대가 재부팅되면 작은 id 쪽의 재시도로 다시 연결된다.
- 국토교통부 보드는 id가 가장 크므로 연결을 시작하지 않고 받기만 한다.

### 4) 동작 제어

- 통신 모듈(`v2v_comm`)은 판단 없이 메시지만 전달하고, 모든 판단은 `wayland_npu_app.c`의 `nc_v2v_decide()`에서 한다.
- 수신한 메시지의 송신 차량 위치, 차선과 내 위치, 차선을 비교해 아래와 같이 동작을 정한다.

```
영상 급정지(brake=1) 수신
  같은 차선, 내가 뒤, 20m 이내   : 앞차 5m 뒤에 정지
  같은 차선, 내가 뒤, 100m 이내  : 속도 20 감속 후 서행
  내가 앞, 다른 차선, 100m 초과  : 무시
  brake 해제 수신               : 원래 속도로 복귀

비상 버튼(SOS) 수신
  같은 차선, 내가 뒤            : 거리와 무관하게 속도 20 감속
  해제 수신                     : 원래 속도로 복귀

차선 변경 신호 수신
  옆 차선, 10m 이내, 상대가 더 빠름 : 5초 대기 후 진행
  그 외                            : 무시
```

- 내 차량의 영상 판단은 앞차가 7m 이내로 접근하면 경고를 켜서 정지하고, 7m 밖으로 멀어지면 해제한다. 경고가 프레임마다 흔들리지 않도록 켜짐 상태를 유지하는 방식(latch)으로 처리했다.
- 정지 중이면 서행 신호가 와도 정지를 우선하고, 이미 서행 중이면 같은 신호가 반복 수신되어도 속도를 더 깎지 않는다.

### 5) 국토교통부 역할

- 별도 보드(vehicle_id 100)가 카메라 영상에서 날씨(맑음, 야간, 야간 우천)와 전방 혼잡도(원활, 보통, 혼잡, 정체)를 분석한다.
- 분석 결과를 차량과 같은 48byte 구조체에 실어 모든 차량에 주기적으로 보낸다. 이때 brake 필드에 날씨, lane 필드에 혼잡도 값을 넣고 나머지 필드는 사용하지 않는다.
- 차량은 id 100에서 온 메시지를 차량 판단 로직에 넣지 않고 최고 속도 상한 계수로만 사용한다. 날씨 계수(맑음 1.0, 야간 0.9, 우천 0.6)와 혼잡도 계수(원활 1.0, 보통 0.9, 혼잡 0.6, 정체 0.3)를 곱해 상한을 정하고, 현재 속도가 상한을 넘으면 상한으로 제한한다.
